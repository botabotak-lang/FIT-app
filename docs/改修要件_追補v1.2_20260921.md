## S1. 帳票の「作業者」と「製造者」のフォント縮小（要望①）
- 疑わしいセルは2つに確定している（全数調査済み）。**両方とも下げて、どちらの解釈でも解消させる**：
  - 作業報告書シートの作業者セル（Q列・全ブロック・現9pt）→ **7pt**。ヘッダー Q9「作業者」（9pt）も7ptに揃える
  - 製造者ラベル BS5（縦書き・現8pt）→ **7pt**
- `scripts/make_template.py` で設定しテンプレート再生成。ExcelJS round-trip 後もフォントサイズが残ることを verify で確認

## S2. Excel→アプリの読み戻し（要望②）
- 新様式（4行ブロック×6シート）の作業報告書と、材料持出表（明細13行＋続き23行×3）をアプリに読み戻す機能を新設
- **新モジュール `lib/reportImport.ts`**（純関数・ブラウザ非依存でテスト可能に）：
  - `parseWorkReportWorkbook(workbook)` → `WorkDayEntry[]`：作業報告書系シートを順に走査し、4行ブロックから 日付（B・空なら直前ブロックから前方補完）／時刻（E/H/K/N 上段=開始・下段=終了、列で種別判定）／作業者（Q）／場所（T）／作業内容（W）を復元。**(日付, 場所, 作業内容の連結) が同じ連続ブロック群は1エントリにまとめ、作業者は和集合**（出力時の「作業者ごと複製」の逆変換）。時間なしブロックの作業内容行は同エントリの内容に改行で連結
  - `parseMaterialsWorkbook(workbook)` → `Material[]`：明細行から 日付/品名/型式/在庫（「✓」→true）/仕入先/数量/単位(AE)/仕入単価/売値単価/送料 を復元。合計行・数式セル（AJ/AS）は読まない（単価×数量で再計算される）。空行スキップ
  - どちらも、値が壊れている行は行番号つきでエラー配列に集めて返す（throwしない）
- **UI**：
  - ステップ2（WorkReportStep）に「Excelから読み込み」ボタン復活：ファイル選択→パース→「現在の作業データ◯件をExcelの内容◯件で置き換えます」確認→反映。**休憩ブロックはExcelに存在しないため、置き換え時に既存エントリの同一日付の休憩ブロックを自動で引き継ぐ**（マージ）。エラーがあれば行番号つきで表示し反映しない
  - ステップ3（MaterialsStep）に「Excelから読み込み」ボタン：同様（材料は全置き換え・確認あり）
- 読み込むのは自アプリが出力した様式が前提。多少の手編集（値の変更・行の追記）に耐えること。テンプレ構造が大きく崩れたファイルは「読み取れませんでした」で拒否

## S3. 帳票一式の工賃集計を単体出力と一致させる（要望③）
- `kind === "all"` でも、材料持出表上段（G/S/Y/AK 列）を **3D数式ではなく `sumHoursByWorker()` の計算値直書き**に変更（単体出力と完全に同じコードパス・同じ数字になる）。M/AE/AO の工賃数式・行9の合計SUM数式は現状維持（値セルを参照するため機能する）
- 保険として、生成する全ブック（3種とも）に **`fullCalcOnLoad`**（開いたとき全再計算）を設定（ExcelJSが対応していなければ xlsxShowZeros.ts と同様のXML後処理で `<calcPr>` に `fullCalcOnLoad="1"` を付与）
- 作業報告書シート右側の集計列（CJ等）の数式は現状維持（印刷範囲外・Excel上の検算用）

## S4. 請求先（顧客）ごとの工賃単価（要望④）
- `supabase/phase_e_customer_rates.sql` を新設（適用は窪田）：`alter table customers add column if not exists labor_rates jsonb;`（null=全体設定を使う）
- `lib/customerMaster.ts`：`laborRates?: LaborRates | null` の読み書きを追加（unit列と同様、**列未適用でも壊れない**エラー再試行つき）
- `lib/laborRates.ts`：`getLaborRatesForCustomer(customerName: string): Promise<LaborRates>` を追加——顧客名（basicInfo.customer は名前文字列）で customers を引き、`labor_rates` があればそれ、無ければ全体設定。**キャッシュは顧客名キーの Map**（既存の単一キャッシュの流用不可に注意）
- 差し込み口3箇所（WorkReportStep / MaterialsStep / InvoicePreviewStep の `getLaborRates()`）を `getLaborRatesForCustomer(basicInfo.customer)` に置き換え。工賃表示・Excel出力の「工　賃(@7,000)」表記は既存の rates 連動で自動追従
- **顧客マスタ画面**（/customers・AdminGate配下）：顧客の編集ダイアログに「この請求先の単価（平日・休日・移動係数）」の3入力を追加。空なら全体設定を使う旨を表示。保存で labor_rates を更新（3つとも空なら null）
- 既存案件の扱いは現状踏襲（出力時点の単価で計算。単価スナップショットは持たない）
