## 3. 「作業報告書」シート仕様（原本準拠）

### 3-1. 構造
- 原本ファイルを**テンプレートとして読み込み**（ExcelJS `workbook.xlsx.load`）、値だけ流し込む方式を採る（1,779個の結合セルをコードで再構築しない）
- テンプレートは原本からデータを消した `public/templates/fit_report_template.xlsx` を作る（数式・書式・結合・印刷範囲・入力規則は残す）
- ページ構成：
  - 1ページ目シート「作業報告書」：行2 タイトル・BU2 年号（令和X年）、行5 船名(C5)/科目(Y5)/型名(BB5)/製造者(BT5付近)、行9-10 表ヘッダー、**行11〜133 = 4行×30ブロック**、印刷範囲 B2:CC133
  - 2ページ目以降「作業報告書 (2)」〜「作業報告書 (END)」：行2-3 表ヘッダー、**行4〜134 = 4行×32ブロック**、印刷範囲 B2:CC134
  - 必要ページ数だけシートを使い、余ったシートは削除しない（原本と同じ6シート構成を維持。数式が `作業報告書:作業報告書 (END)` の3D参照のため）
- 右側 CF〜EB 列（印刷範囲外）：作業者別の所要時間集計。数式 `=IF(Q11="大竹",E14-E11,0)` 形式で作業者名がハードコード → **社員マスタ（有効・sort_order順）から作業者名を流し込んで数式を再生成**する（5枠：CF/CP/CZ/DJ/DT。5名超は切り捨てず6枠目以降を同パターンで追加）
- 行136-141：早出(始/終)・時間外(始/終)しきい値、作業者名リスト(Q137〜)、合計（BZ138〜141＝全員合計、CJ138〜141＝作業者別合計）。作業者名リストも社員マスタで置換

### 3-2. 1ブロック（4行）の書き込み
| セル | 内容 |
|---|---|
| B（4行結合） | 日付。同一日の2ブロック目以降は空欄（原本準拠：日付は日の先頭ブロックのみ） |
| E/H/K/N の上段 | 開始時刻（`h:mm`）。列は種別で選ぶ：移動=E、作業内(平日)=H、作業外(平日)=K、休日=N |
| E/H/K/N の下段（+3行） | 終了時刻 |
| Q（4行結合） | 作業者（複数なら「、」区切り。集計数式は先頭1名にしか合致しないため、複数作業者の場合は**作業者ごとにブロックを分けて出力**する） |
| T（4行結合） | 場所 |
| W:CC（4行結合） | 作業内容 **1行分**（入力欄の改行で分割した1行。自動折返しなし・wrapText=false） |

- アプリの1作業日（WorkDayEntry）→ 出力ブロック列の生成規則：
  1. 時間ブロックを開始時刻順に並べ、`break`（休憩）は**出力しない**（前後のブロックが分かれていることで表現）
  2. 作業内容を改行で分割した行 L1..Ln
  3. i番目の時間ブロックに Li を割り当て、時間ブロックより行が多ければ時間なしブロックで続ける。時間ブロックより行が少なければ作業内容空欄で時間だけ出す
  4. 日付は当日の先頭ブロックのみ
- 作業者が複数の日は、作業者ごとに同じ時間ブロック群を複製して出力（工賃は人数分＝現行アプリの計算と同じ）

### 3-3. 検証
- 出力ファイルを openpyxl で読み戻し、結合セル数・印刷範囲・行高・数式（CJ列）が原本と一致することをスクリプトで確認
- サンプル案件（原本のStarLink案件相当のデータ）を入力して出力し、原本1ページ目と目視比較できるPDF/PNGを `docs/verify/` に置く（Googleドライブ変換 `_COMPANY/CDO/google_workspace/gdrive_export.py` を使用可）

## 4. 「材料持出表」シート仕様（原本準拠）

- 1ページ目シート「材料持出表」（印刷範囲 A1:BB25）：
  - 行1：船名(D1)・科目(S1)・型名(AH1)・完成月日(AX1)
  - 行2〜9：作業者別工賃集計（A=氏名、G=平日時間(内)、M=工賃@7000 `=(G*24)*7000`、S=平日時間(外)、Y=休日時間、AE=工賃@8400、AK=移動時間、AO=移動費 `=(AK*24)*5600`、AU=備考）。氏名は社員マスタ順。時間は作業報告書シートの集計セルを参照する数式のまま（`=SUM('作業報告書:作業報告書 (END)'!CJ139)` 等）を作業者枠に合わせて再生成
  - 行10：タイトル、行11：ヘッダー、**行12〜24：明細13行**
  - 行25：持出者(Z25)・仕入合計・売値合計
  - 行27以降：入力規則用リスト（✓/在庫外、仕入先14社）はテンプレートのまま残す
- 2ページ目以降「材料持出表 (2)」〜「(4)」：行3〜25の**23行**、行26に合計
- 明細1行の列：A=月/日、E=品名、M=型式、U=在庫（isStock→「✓」／false→空欄）、X=仕入先、AB=数量、AE=単位（Phase Cまで空欄）、AF=仕入単価、AJ=仕入合計（数式維持）、AO=売値単価、AS=売値合計（数式維持）、AX=送料
- ステップ3に「材料持出表をExcel出力」ボタン（材料持出表シートのみのブック）。ステップ4に「帳票一式をExcel出力」（作業報告書＋材料持出表）

## 5. Phase C 詳細（本番DBスキーマ変更を伴う・窪田承認後に着手）

- `products` に `unit text not null default ''` を追加（SQLは `supabase/` に置く。適用は窪田）
- 新テーブル `app_settings (key text primary key, value jsonb, updated_at)`。`labor_rates` キーに `{regular:7000, holiday:8400, travelFactor:0.8}`。未設定時はコード既定値
- `lib/laborRates.ts`：取得（キャッシュ）＋更新。`calcLaborCostForEntry` 等は単価を引数で受ける形に変更
- 管理画面 `/settings`：工賃単価の編集。`/products` `/customers` `/employees` `/settings` の入口に `AdminGate` コンポーネント（`NEXT_PUBLIC_ADMIN_PASSWORD` と照合、sessionStorageに合格フラグ）
- Material に `unit: string` 追加（既存データは ''）。MaterialsStep/MaterialsForm に単位入力（datalist候補：本・個・袋・m・台・式・セット・巻）。製品マスタ選択時はマスタの unit を初期値に
- Excel出力の AE列・工賃集計の単価定数を設定値に差し替え
